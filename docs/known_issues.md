# 原有问题与使用限制

以下问题在导入时发现。为保持实验来源可核对，归档源码和依赖补丁未作修复，服务器原文件也未修改。

| 位置 | 现象与影响 |
| --- | --- |
| 第一处两套 `Test_blas/libenv.sh` | 最后一条 `GOMP_CPU_AFFINITY` 缺少闭合引号，`bash -n` 失败；文件还包含示意性的 `./yourprograme` 命令，不能直接作为环境脚本 source |
| 第一处顶层 `OpenBLAS` 补丁 | `driver/level3/level3.c` 混入孤立的 `·` 字符；保留补丁供检查，不建议直接用于构建 |
| 第二处依赖补丁 | 有大量可执行权限变化；BLIS / LIBXSMM 部分符号链接变成短文本文件，属于当前工作区状态，不代表计算优化 |
| 第一处 `BLAS_Openlib/Test_blas/libxsmm/` | 找到运行脚本与结果，未找到其同目录的 `gemm_bench_libxsmm_nt.c`；没有拿另一来源的源码冒充补齐 |
| 第一处 BLIS 专用目录 | `run_nt.sh` 按命名参数调用主测试，但专用程序接收位置参数；`run_nt_blis.sh` 使用匹配的参数格式，GFLOPS 字段仍可能带 `GFLOPS=` 前缀 |
| `Test_blas/shalom/` | 保留开发中的测试入口；未验证其参数与通用运行脚本兼容，也未执行完整 LibShalom 构建 |
| 第二处原始 Makefile | 默认依赖前缀与当前安装状态不同，直接执行可能找不到头文件；可覆盖 Makefile 变量或使用实际路径 |
| 所有 `fp64_peak.c` 副本 | 缺少 `<stdlib.h>`，GCC 对 `strtoull` 报隐式声明警告；NEON 循环实际有 16 条 FMA，但 FLOP 统计按 32 条计算，输出不能直接作为可靠峰值或归一化分母 |
| 第二处 `fp64_peak_sve.c` | 同样缺少 `<stdlib.h>`；当前 GCC 10.3.1 在 `-O3 -march=native -ffast-math -fopenmp` 下出现内部编译器错误，未通过该配置的编译 |
| 原始结果 | 有仅表头的 CSV、带 `#` 环境注释的 CSV，以及平均值 / 最短时间等不同统计方式；原始内容保留，不能不经核对直接汇总 |
| 合成峰值测试 | 本次仅做短迭代运行检查，未检查生成汇编、频率、核心隔离、指令吞吐或完整数值正确性，不能据此报告硬件峰值 |

主测试程序没有完整的数值正确性检查，也没有全面处理缺失参数、负维度、整数溢出等非法输入。运行时使用可信的正数形状和重复次数；对外提供通用工具前需另行修正这些入口。

本仓库没有宣称归档的性能结果已完整复现论文、图示与测量平台的全部组合。原始来源标签表示文件从何处导入，不自动证明历史测量的平台身份。
